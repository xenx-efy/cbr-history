## Найденные баги и замечания

### Баг №1: Сбой при наличии пустых файлов-заглушек в data/

**Сценарий:** если в каталоге `data/` есть файл `*.xml` нулевой длины (0 bytes), `load_existing()` (строка 20) пытается распарсить его и падает с `ParseError: no element found: line 1, column 0`.

**Симптом:** все три ленты выдают ошибку при первом запуске, если в `data/` были пустые файлы.

**Вероятность в продакшене:** низкая — в GitHub Actions всегда чистый checkout. Однако при локальной разработке или ручном развёртывании может возникнуть, если создать `touch data/rssnews.xml`.

**Фикс** (строка 28 — `load_existing`): обернуть `ET.parse()` в `try/except ET.ParseError` и возвращать `(None, None, {})` при повреждённых или пустых файлах:

```python
def load_existing(path: pathlib.Path):
    if not path.exists():
        return None, None, {}
    try:
        tree = ET.parse(path)
    except ET.ParseError:
        return None, None, {}
    root = tree.getroot()
    ...
```

### Баг №2: Повреждённый существующий файл не восстанавливается автоматически

**Сценарий:** файл `data/*.xml` повреждён (обрезан посередине, дублирован, заменён бинарным мусором).

**Симптом:** скрипт выводит `название: ошибка опроса — not well-formed (invalid token): line X, column Y`, файл остаётся в повреждённом состоянии навсегда (даже если сеть доступна и ЦБ отвечает).

**Анализ:** это следствие того же бага №1 — `ET.ParseError` не обрабатывается внутри `load_existing()`, а пробрасывается наружу и ловится общим `except` в `poll_all()`. Файл не удаляется и не перезаписывается.

**Фикс:** тот же, что в баге №1 — обрабатывать `ParseError` в `load_existing()`. После фикса повреждённый файл будет считаться «не существующим» и скрипт выполнит полную перезагрузку при следующем запуске.

### Замечание: отсутствует User-Agent

Скрипт не передаёт заголовок `User-Agent` при HTTP-запросе. httpx по умолчанию использует `python-httpx/<version>`, что некоторые серверы могут блокировать.

**Рекомендуемый фикс** (строка 39):

```python
headers = {"User-Agent": "CBR-Poller/1.0"}
resp = httpx.get(url, timeout=15, headers=headers)
```

### Замечание: нет обработки `resp.raise_for_status()` отдельно от остального кода

`raise_for_status()` на строке 40 выбросит исключение при HTTP-ошибке (4xx/5xx). Это перехватывается `poll_all()`, что корректно. Однако диагностика могла бы быть точнее, если делить ошибки HTTP и ошибки парсинга.

### Замечание: хардкод URL-ов

URL-ы фидов зашиты в `FEEDS` прямо в коде. Для PoC это приемлемо, но на будущее можно вынести в конфигурационный файл.

### Замечание: `git add data/` в workflow

Файлы `data/*.xml` сохраняются в git. Каждые 15 минут создаётся коммит с изменениями этих файлов. Это может привести к раздуванию истории репозитория (каждый коммит ~850 KB). Рекомендуется рассмотреть:
- Использование Git LFS для XML-файлов
- Или выгрузку данных в отдельное хранилище, коммитя только при значимых изменениях
